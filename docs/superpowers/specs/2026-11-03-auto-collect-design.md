# 記録の自動収集（Google Apps Script）設計書

作成日：2026-11-03
元の設計：`2026-11-03-spider-discussion-design.md`

## 1. 目的

記録係が討論を「終了」すると、その記録が自動で先生の Google ドライブに集まり、
先生は教員画面で日付を選ぶだけで全班の記録を見られるようにする。

## 2. 決めたこと

- 届く時期：記録係が「終了」したとき（討論中のリアルタイム表示はしない）。
- 教員画面での分け方：日付だけ。
- 作り方：アプリ全体を Apps Script のウェブアプリとして公開する（方式 A）。
  - 実行するユーザー：先生（デプロイしたユーザー）
  - アクセスできるユーザー：学校のドメインの全員
- GitHub Pages 版は予備（ファイル提出方式）としてそのまま残す。

## 3. 仕組み

- 受け取り先：先生のドライブのスプレッドシート（Apps Script はこのスプレッドシートに付ける）。
- シート「記録」の列：受信日時／日付／班／テーマ／送信者／記録ID／記録（JSON）。
- 同じ記録ID が再び届いたら、行を増やさず上書きする。
- Google 側の関数：
  - `submitRecord(text)`：だれでも（学校のアカウントなら）呼べる。形式を確かめて保存。
  - `isTeacher()`：開いている人がデプロイした先生本人か。
  - `listDates()`：先生だけ。日付と件数の一覧。
  - `getRecords(date)`：先生だけ。その日付の記録。
- シートに書く文字は先頭に `'` を付け、日付の自動変換や数式としての実行を防ぐ。
- 書き込みは LockService で順番待ちにする。
- 記録（JSON）が 45,000 文字を超えるものは受け取らない（セルの上限 50,000 文字）。

## 4. アプリ側

- 記録に固有の番号 `id` を付ける（書き出しの項目にも加える。`version` は 1 のまま、`id` は省略可）。
- 送信待ち（端末の localStorage `spider.outbox`）：
  - 結果画面を開くと、その記録を送信待ちに入れて送る。
  - Google 側が `{ ok: true }` を返したときだけ送信待ちから消す。
  - アプリを開いたとき、通信が戻ったとき、30 秒ごとに送り直す。
- 結果画面に送信の状態を出す：「先生に送りました」「送信待ち：通信がつながると自動で送ります」。
- ホーム：Apps Script 版では、先生のアカウントのときだけ「教師として使う」を出す。
- 教員画面：Apps Script 版では、日付を選ぶとその日の記録を読み込む。「更新」で読み込み直す。ファイルの読み込みも残す。
- Google との通信は `js/remote.js` にまとめる。`google.script.run` がない（GitHub 版）ときは送信機能なしで今までどおり動く。
- 画面の切り替えは、動的 import をやめて通常の import にする（1 ファイルにまとめるため）。
- サービスワーカーは GitHub 版でだけ登録する。

## 5. Apps Script 用のまとめ

- `npm run build:gas` で `gas/build/` に次を作る：
  - `index.html`：`index.html` に CSS と全 JS を埋め込んだもの。各 JS ファイルは関数で包み、import を変数の受け渡しに置き換える。
  - `Code.gs`、`appsscript.json`：`gas/` からコピー。
  - `preview.html`：Google の代わりのにせもの付き（手元の確認用。Apps Script には送らない）。
- Apps Script への送り込みは clasp を使う。使えない場合はファイルを貼り付ける手順を README に書く。

## 6. テスト

- 送信待ち・送り直し：にせものの Google を使って Node でテスト。
- Google 側の関数：にせものの SpreadsheetApp・Session・LockService を使って Node でテスト（上書き、先生だけの制限、形式の確認、`'` の付け外し）。
- まとめた HTML：構文の確認と、`preview.html` をブラウザで通して操作。
- 公開後：先生のアカウントで記録係・教員の両方を試す。生徒アカウントでの確認は先生にお願いする。

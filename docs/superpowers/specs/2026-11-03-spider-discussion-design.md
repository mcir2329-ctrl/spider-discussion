# スパイダー討論 記録アプリ 設計書

作成日：2026-11-03

## 1. 目的

スパイダー討論（Spider Web Discussion）で、班ごとの話し合いの流れを記録・可視化する。
Equity Maps のように座席図で発言者をタップし、発言のつながりを蜘蛛の巣状の線で描く。
討論後に各班の記録を教師へ提出し、教師は全班を並べて比較する。

## 2. 前提と制約

- 動作環境：Chromebook（Chrome ブラウザ）。画面はおよそ 1366×768、タッチ操作とマウス操作の両方に対応する。
- 利用者：
  - 記録係（各班 1 名の生徒）：自分の Chromebook で記録する。
  - 教師：提出ファイルを読み込んで集約する。
- サーバーは使わない。データはその Chromebook の中にだけ保存し、外部へ送信しない。
- 配布：GitHub Pages などの静的ホスティングに置き、URL を Google Classroom で配る。
  一度開いたあとは通信なしで動く（PWA）。ホーム画面への追加に対応する。
- 技術：HTML・CSS・JavaScript のみ。ビルドツールや外部ライブラリは使わない。

## 3. 対象外（このバージョンでは作らない）

- 音声の録音・自動分析（Hylable 型）
- 手描き入力（スマートペン型）
- リアルタイムの共有・同期
- 教師から記録係への設定（名簿・座席・発言の種類）の配布
- 発言ごとの文章メモ

## 4. 画面と操作

アプリは 1 つで、最初に「記録係として使う」「教師として使う」を選ぶ。

### 4.1 準備画面（記録係）

- 入力項目：班の名前、討論のテーマ、人数（2〜12 人）。
- 座席の並び：「円形」「長方形」「自由配置」から選ぶ。選ぶと席が自動で並ぶ。
- 各席に名前または出席番号を入力する。席はドラッグで移動できる。
- 発言の種類：初期値は次の 5 つ。名前と色を変更・追加・削除できる（最大 8 個）。
  - 質問／根拠／反論／つなぐ／まとめ
- 設定はその Chromebook に保存され、次回は「前回の設定を使う」で呼び出せる（最大 10 件まで保存し、古いものから消える）。

### 4.2 記録画面（記録係）

- 座席図を画面いっぱいに表示する。
- 「開始」で記録を始め、経過時間を表示する。
- 席をタップすると、その人を新しい発言者として記録する。
  - 直前の発言者からその人へ線を引く。最初の発言は線を引かない。
  - 同じ人を続けてタップした場合は、新しい発言として数えるが線は引かない。
  - 同じ 2 人の間のやりとりが増えるほど線を太くする（向きは区別せず、本数で太さを決める）。
- タップ直後、画面下に発言の種類のボタンを表示する。押すのは任意。
  - 押すと、その発言に種類が付く。
  - 次の人をタップするまでは、種類を付け直せる。
- 線と種類の表し方：
  - 2 人の間の線は 1 本にまとめ、灰色で描く。やりとりの回数が多いほど太くする。
  - 最後に引いた線だけは強調して描き、その発言に種類が付いていれば種類の色にする。
  - 種類は、各席のまわりに小さな色の点（種類 1 回につき 1 個）で表す。
- 「取り消し」：最後の発言を 1 件ずつ取り消す。回数の制限はない。
- 「一時停止／再開」：一時停止中はタップを受け付けず、時間も数えない。
- 「終了」：確認を出したうえで記録を終え、結果画面へ移る。
- 発言時間：ある人をタップしてから、次の人をタップする（または一時停止・終了する）までを、その人の発言時間とする。一時停止していた時間は含めない。

### 4.3 結果画面（記録係）

- 完成した蜘蛛の巣の図を表示する。
- 一人ずつの集計：発言回数、発言時間の合計、発言の種類ごとの回数。
- 発言が 0 回の人は、図と表の両方で目立たせる。
- 班全体の集計：発言の総数、討論の時間、発言の偏り（最も多い人と最も少ない人の回数）。
- 「提出用に保存」：次の 2 つのファイルを保存する。
  - 記録ファイル `班名_日付.json`（教師が読み込む用）
  - 図の画像 `班名_日付.png`（そのまま見る用）
- 「記録に戻る」で、終了を取り消して記録を続けられる。

### 4.4 集約画面（教師）

- 複数の記録ファイル（`.json`）をまとめて選ぶか、画面にドラッグして読み込む。
- 班ごとの蜘蛛の巣を並べて表示する。クリックすると大きく表示し、その班の集計を見られる。
- 班の比較表：班名、テーマ、人数、発言の総数、討論の時間、発言 0 回の人数、発言の種類ごとの割合。
- 比較表を CSV で保存できる（Excel やスプレッドシートで文字化けしないよう、UTF-8 の BOM を付ける）。
- 読み込めなかったファイルは、ファイル名と理由を一覧で示し、ほかのファイルの表示は続ける。

## 5. ファイル構成

```
index.html          画面の骨組み
css/style.css       見た目
js/app.js           画面の切り替え
js/model.js         記録データの形、操作（発言の追加・取り消しなど）、集計
js/web.js           蜘蛛の巣の図を SVG で描く（記録・結果・集約で共通）
js/setup.js         準備画面
js/record.js        記録画面
js/result.js        結果画面
js/teacher.js       集約画面
js/storage.js       端末への保存と読み込み、ファイルの書き出しと読み込み
sw.js               通信なしで動かすためのサービスワーカー
manifest.json       ホーム画面への追加の設定
tests/index.html    model.js のテストページ（ブラウザで開くと結果が出る）
```

`model.js` は画面に依存しない。画面の各ファイルは `model.js` の関数を呼び、受け取った状態を描く。

## 6. 記録データの形

```json
{
  "app": "spider-discussion",
  "version": 1,
  "group": "3班",
  "topic": "討論のテーマ",
  "date": "2026-11-03",
  "layout": "circle",
  "members": [
    { "id": "m1", "name": "12", "x": 0.5, "y": 0.1 }
  ],
  "types": [
    { "id": "t1", "label": "質問", "color": "#2f6fdd" }
  ],
  "turns": [
    { "member": "m1", "start": 0, "duration": 34.5, "type": "t1" }
  ],
  "startedAt": "2026-11-03T10:15:00+09:00",
  "totalSeconds": 900
}
```

- 座席の位置 `x`・`y` は、図の幅と高さに対する割合（0〜1）で持つ。画面の大きさが違っても同じ配置になる。
- `start` は討論の開始からの秒数（一時停止の時間を除く）。`type` は付いていなければ `null`。
- 線は保存しない。`turns` の順番から毎回つくり直す。取り消しても記録と図がずれないようにするため。

## 7. 保存と不具合への備え

- 記録中は、タップ・種類の付与・取り消しのたびに、端末（localStorage）へ自動で保存する。
- アプリを開いたとき、終わっていない記録があれば「続きから記録する」「破棄する」を選ばせる。
- 教師が読み込むときは、`app` と `version` を確かめる。形式が違うものや壊れたものは読み飛ばし、理由を示す。
- 名前は端末の外へ送らない。提出ファイルに名前を入れたくない場合は、出席番号で入力するよう案内する。
- 端末の保存が使えない場合（容量不足など）は、記録は続けたうえで、警告を出し、こまめに「提出用に保存」するよう促す。

## 8. テスト

- `model.js` のテスト（`tests/index.html`）：
  - 発言の追加、同じ人の連続、取り消し、一時停止を挟んだときの発言時間
  - 一人ずつ・班全体の集計、種類ごとの回数、発言 0 回の人
  - 線のつくり直し（2 人の間の本数、向きを区別しないこと）
  - 記録ファイルの書き出しと読み込み、形式の違うファイルを読み飛ばすこと
- 画面の確認：1366×768 程度の画面で、準備 → 記録 → 結果 → 提出用に保存 → 教師画面で読み込み、の流れを実際に操作して確かめる。通信を切った状態で開き直しても動くことを確かめる。
